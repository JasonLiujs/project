# 重复演示恢复说明

远端基线分支和标签均为 `demo/openfront-warship-buggy-v1`。该引用始终保存未修复
状态，不在演示过程中合并修复 PR。

每轮演示：

1. 新建一张飞书项目缺陷单。
2. CodeM 从基线分支创建全新沙箱。
3. 在本工程目录执行 `npm run inst` 和 `npm run demo:start`。
4. 修复 Agent 创建唯一的 `fix/warship_diagonal_<工作项ID>_<运行后缀>` 分支。
5. 展示修复、测试和 PR，但不要合并 PR。

演示结束：

1. 停止预览进程并销毁本轮 CodeM 沙箱。
2. 关闭本轮 PR，删除本轮远端修复分支。
3. 下一轮重新从基线分支创建沙箱。

不要在复用工作目录中执行 `git reset --hard`。新沙箱天然恢复到带 Bug 状态，
同时不会覆盖上一轮留下的日志或客户现场证据。
